# 京东自动混剪 · V2 开发版

独立 Windows 桌面软件，正式工程：**E:\京东自动混剪\studio**。
第二版改为 **商品标题 → 脚本/口播 → 画面识别与匹配 → Fish 配音 → 实测时长合成**。
旧工程 `E:\京东带货`、旧程序及既有交接包保持只读；不安装或修改旧工程依赖。

## 启动

本机双击 `E:\京东自动混剪\studio\启动混剪工作台.vbs`，或运行：

```powershell
Set-Location -LiteralPath 'E:\京东自动混剪\studio'
.\.venv\Scripts\python.exe -B -X utf8 app.py
```

新电脑先准备 Python 3.12 x64、Microsoft Edge WebView2 Runtime，以及 PATH 中的
FFmpeg/ffprobe，再在工程目录运行 `install.ps1`。安装使用 `requirements-lock.txt`；
当前交付是源码启动版，不是免安装 EXE，不附模型、依赖环境或用户视频。
历史本机环境：Windows 10 19045 / Python 3.12.14 x64 / WebView2 146.0.3856.62。
Windows 11、全新电脑、NVENC/QSV及 CUDA 尚未完成实际验收；默认 CPU 编码、1 路合成。

## 使用顺序

### 文案流程更新（2026-10-21，取消强制审核）

- 修正有标题与具体 Hz 数值依据的显示器/电视刷新率表述，以及“清晰展示”等有限拍摄指令的字面误判；不把“低蓝光”扩写为已核实护眼等效果。
- 按用户最新要求取消强制文案审核：生成后可编辑，时长合适即可由用户确认进入画面匹配，不再显示“核对并保存”或因旧 `fact_status` 阻挡操作。
- 已有待核对稿直接沿用，不要求重新生成、重存或迁移数据库。新建/编辑稿以 `fact_status=not_required` 表示无需审核，不冒充已核实商品事实。
- 编辑保存不再执行商品主张审核，也不调用模型；保存后仍需重新匹配画面。模型提示词继续要求依据商品标题写作，不添加虚构参数。
- 内容结构损坏、占位符或非法路径等仍会报错；未新增自动模型重试。历史已失败任务没有保存原稿，本次不伪造恢复。
- 继续检查空文案、格式、时长、素材完整性、镜头覆盖及用户付费确认；本次不自动匹配、配音或合成。
- 本轮证据：`E:\京东自动混剪\studio\verification\no-claim-gate-20261021\VERIFICATION.txt`；离线/模拟测试不等于真实画面匹配完成。

1. **本地素材库**：选择自己的文件夹并读取 MP4/MOV/MKV/WebM/M4V，当前只扫描一层。
   原视频按路径引用，不移动、不覆盖。可以预览、勾选和刷新。
2. **抖音素材库**：粘贴多行链接或完整分享文案；**回车只换行**。
   点“解析并下载”才提交，最多 50 条、2 路并发。“清空”只清输入框，不删文件、不取消任务。
   下载目录在设置页单独指定，不切换本地素材文件夹；完整校验后自动入抖音库，最新在前。
3. 两个库的勾选可累计；相同内容去重后一起进入混剪工作台。一次选 1～50 条同商品素材。
4. 顶部粘贴京东链接，点击读取。标准商品链接优先读取京东手机版公开页面中的完整商品标题和同 SKU 数据，
   不加载图片、视频及网页脚本；快速路径最多等待6秒。没有有效标题时才打开独立商品窗口，
   由用户完成必要的加载、登录或验证。分享短链接仍使用窗口路线。
   程序不让模型猜商品名，也不采用网页截断标题或推荐商品名；核对结果后继续。
   2026-10-21已用SKU10144049649180实际验证快速读取，单次约1.9秒；其他链接与平台变化需分别验证。
5. 选择参考秒数和条数，确认调用 DeepSeek，点击生成。默认 **25 秒、1 条**；
   参考输入 **5～60 秒**，每次 **1～5 条**。页面只展示可编辑口播，不展示内部脚本、镜头提示或 ID。
   商品标题是唯一商品事实依据：标题没给出的参数、材质、优惠和功效不应生成成事实；
   这些是写作要求，不设强制文案审核或核对保存步骤。
6. 确认文案后，显式确认“分析并匹配画面”。本地 FFmpeg 抽帧，GLM-5.3-Flash 视觉识别商品和干扰，
   DeepSeek 按分句需求选择已分析片段。新流程**不先跑 ASR**。
   画面不足或低置信度保持待核对，可预览、在可用片段中手动替换；不随机补镜头。
7. 匹配完成后确认 Fish 配音。默认音色 `be40aff9ee7b4d0cba3bb35e924d85b2`，可在设置更换。
   逐句测量真实音频时长，画面从本句相关候选自动补足；先不同镜头，再有限复用，仍不足时统一加速配音至最多1.5倍。
8. 成片按真实配音时长剪辑，**每条与参考时长相差不超过 5 秒，且绝不超过 60 秒**。
   选择 60 秒时须为 55～60 秒。超出范围会停止发布、保留已生成配音；不截断旁白，
   不自动重写或重复付费。调整文案后由用户重新确认。
9. 导出支持中文字幕、顺滑转场、BGM、原声移除、编码速度及 1～3 路合成。
   硬件编码失败可回退 CPU，但不代表当前显卡和新电脑已实测。

## 设置、画面识别与边界

- DeepSeek、Fish、**智普 GLM API Key**只在设置输入，采用当前用户 DPAPI 保存。
  默认 `glm-5.3-flash`，官方接口 `https://open.bigmodel.cn/api/paas/v4/chat/completions`；
  使用智普标准模型 API 密钥，不沿用旧千问密钥。旧配置只在内存迁移，原密钥文件保留。
- 视觉是抽样而非逐帧扫描：每个最多 **3 秒**窗口计划 **5 张**关键帧，每源最多 **90 窗**。
  超长视频均匀取窗；每批最多 **2 窗/10 图**，每源最多 **45 次**视觉请求。
  极短尾窗的相同图片去重，实际传送 1～5 张并如实标注。成功批次缓存；新采样版本与旧缓存隔离。
  后续 DeepSeek 按语义分批返回相关镜头候选；大素材集合可能多次请求，显示进度、可取消。
  未覆盖区域不自动入选；瞬间闪帧和细节可能漏检。黑屏本地检测；其他商品、二维码等由视觉结果筛选。
  原视频保持不变。
- DeepSeek接收商品标题、口播或画面描述；Fish接收配音文字；GLM接收抽样 JPEG 和商品标题。
  不把完整源视频上传给这些接口。抽样图片会发送至配置的官方视觉接口。
- 模型生成、画面分析/匹配和配音均须本次明确确认。收费请求无自动重试；视觉已完成批次、
  已验证配音可缓存复用。结果不确定时保留记录，核对服务端后再手动重试。
- 取消本地请求不等于撤销服务端计费；视觉请求单次阻塞 socket 最长可能等 120 秒，其他模型请求为 60 秒。
  重启后的未完成任务标为中断，不自动恢复收费操作。
- 去字幕/去水印仍是手动区域 blur/delogo，可在清理区域叠加常驻字幕底板；不是 AI 无痕修复。
  新字幕在转场后叠加。不同素材位置、长字幕分页、修复痕迹和匹配语义均需预览。

## 开发与测试

### 尾帧抽取（2026-10-21）

- JPEG 抽帧显式使用完整色彩范围；尾部请求时间可能仍在视频时长内，却晚于最后一帧的时间戳。
  遇到空输出时，仅在当前短片段窗口内查找真实视频帧，按整数 PTS 取帧，避免小数 seek 舍入再次越过尾帧。
- 这只是有界的本地抽帧回退，不会自动重试云端请求；空窗口继续报错，真实黑帧仍按质量规则排除。
- 保留缓存版本、原计划和片段 ID；已经成功缓存的片段无需重新抽帧或提交识别。
- 历史失败任务保留，不因升级改成成功。升级后的本地回归、真实素材抽帧和模拟接口验证见
  `E:\京东自动混剪\studio\verification\tail-frame-20261021\VERIFICATION.txt`。
  本轮不追加收费调用，也不等同于完整真实匹配或同 SKU 质量验收。

### 文案时长与配音倍速（2026-10-22）

- 生成文案仍按每秒 4 个计时单位、参考 ±5 秒预算；25 秒目标优先约 100 字，常速预算 80～120 字。
  汉字、字母、数字各计 1，标点不计；这是预估，不是音色实测语速。
- 预估略长时不再强制删字：最高 1.5 倍配音能适配就可继续自动匹配画面。
  例如 122 字预估 30.5 秒，约 1.017 倍即可进入 30 秒；不要求删 2 字或重新生成文案。
- 25 秒目标下可适配上限为 180 字；更长或不足 80 字时仍保留原文并提示调整。
  已存草稿重新按正文判断，不因旧的“待调整时长”标记锁住按钮，不改写历史任务记录。
- 配音后仍以实测时长重新规划：优先不同相关镜头，再有限复用，必要时统一变速，最高 1.5 倍。
  成片须满足参考 ±5 秒且不超过 60 秒；预估可匹配不等于素材充足或成片已经生成。
- 本次修改不自动调用模型；用户确认后才进入收费分析/配音。
  证据及回滚：`E:\京东自动混剪\studio\verification\speed-aware-copy-20261022`。

## 2026-10-22 自动时间线更新

- 预估匹配、手动选择、配音前检查、实测配音后排片共用 `mixstudio/timeline.py`。
  一个口播句可以自动串接多个相关镜头；候选共享不等于最终复用。有限多顺序分配，不声称数学最优。
- 同一成片的原视频时间范围最多出现2次，总额外使用最多2次；原文件 SHA256 + 原始区间计数。
  重命名、字节相同副本、程序内部再次裁剪不重置计数。外部重新编码/裁剪再导入后若没有来源映射，
  目前不做跨文件视觉指纹溯源，不承诺自动识别为同源。
- 优先补不同相关镜头→有限复用→统一最小必要配音倍速(1～1.5)。FFmpeg atempo保持音高，
  不加速画面。保留原始配音缓存，只处理工作副本；字幕按处理后的实测音频计时。
- 统一计算转场消耗；成片仍满足参考±5秒且≤60秒。实测后仍不足时列出所有缺口，不假装完成，
  不自动改写或重复付费。已有ready草稿可在响应中本地生成估算计划，不强制重跑视觉。
- 素材库与混剪台各最多显示20条任务，活动任务优先，长错误折叠，列表内部滚动。
  完整任务详情仍保存在运行目录的 state.sqlite；logs/tasks-日期.jsonl 追加不含密钥的状态事件，
  不记录请求正文、原始错误或用户路径；可从界面打开日志目录。
- 本次准确测试、安装状态与回滚：`E:\京东自动混剪\studio\verification\auto-timeline-20261022\VERIFICATION.txt`。
  仅本地合成及模拟云端测试；GLM真实识别效果和真实配音商品成片另行确认。

### 视觉响应编号（2026-10-22）
模型只需返回本批c1/c2短编号，程序严格映射回原始片段ID；返回顺序可以变化，但编号缺失、
重复或未知时仍停止该批。原有已验证缓存、采样计划和商品关联判断保持不变。
从失败任务手动重试会先加载成功缓存，再处理剩余片段；失败历史不会改成成功。

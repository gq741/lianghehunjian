# 运行稳定性修复方案（对应 BUG_REPORT_20261023.md 的 A~E 组问题）

| 项目 | 内容 |
|---|---|
| 目标 | 解决"跑不起来、越用越卡、白花钱、成片假失败、磁盘爆"这 10 个影响日常运行的问题 |
| 前提 | 只改本工程；不动用户素材；不替换架构；不产生付费接口调用（验收除外，需单独授权） |

## 2. 逐项方案

### 2.1 京东商品读取（问题 1）

**现象**：① `https://u.jd.com/xxx，复制此链接打开京东` 被判"链接无效"；② 多规格商品走弹窗读取时，拿"页面上第一个规格"去和链接比，对不上就永远等，3 分钟后超时。

**根因**：
- 链接识别把中文和全角标点一起吞进地址（`product.py:16-19`），只对结尾去标点，末尾是中文就无效。
- 弹窗读取的脚本把"链接里的商品编号"当作读到的编号（`product.py:211-213`），再拿去和链接比必然相等，等于没校验；而取的是页面第一个规格按钮，不是选中项。
- 弹窗存在时每 0.2 秒查一次页面，快速失败时在空转。

**改法**：
1. 链接识别只接受英文 URL 安全字符；或先按"空白 / 中文标点"切分，再逐个校验；错误提示分三种：没找到链接、找到多个、不是京东商品页。
2. 弹窗脚本改读"已选中规格"的编号（选中样式或 `aria-checked`），读不到时退回链接编号；把"京东商城首页/正品低价…"这类通用标题、超长标题的拒绝规则也用在弹窗通道。
3. 页面查询降频：每秒最多一次，且页面没加载完时先等。

**改完效果**：微信里的三种常见分享文案都能直接读；多规格商品不再白等 3 分钟；读到"京东商城首页"会明确提示而不是当商品标题。

**验证**：三种分享文案（链接后接中文、全角逗号、纯链接）各测一次；一个多规格商品页；一个未登录页面。全程不花钱。

**风险**：京东页面结构变化会影响弹窗读取；因此保留"读不到就提示手动复制标题"的兜底。

### 2.2 导入/分析卡顿（问题 2）

**现象**：1GB 视频导入/匹配要几分钟；取消后半天没反应。

**根因**：分析画面时"开始、每批前后、结束"都重新算整文件校验码（90 段要算 92 次）；个别格式探测会把整文件帧信息全导出来。

**改法**：
1. 开始算一次完整校验码；之后只比对"文件大小 + 修改时间 + Windows 变更时间"（仓库已有现成实现 `media_identity.py`）；结束时复用最后一次结果。
2. 所有校验循环加取消检查（现在有一处写死不可取消）。
3. 探测"没有时长信息"的文件时，只读文件头尾片段或改用帧数统计，不整文件导出。
4. 导入/分析进度里显示"正在校验/正在分析"，让用户知道在做什么。

**改完效果**：1GB 素材整文件读取从 92 次降到 ≤2 次；取消 0.2 秒内生效；导入不再莫名超时。

**验证**：统计整文件读取次数；中途取消；一个无时长字段的 MKV。

**风险**：理论上"大小和时间都没变但内容被换"检测不到；保留"开始+结束"两次全量校验兜底。

### 2.3 越用越卡、假断线（问题 3，影响最大）

**现象**：用一两个月后界面明显变慢；某次刷新转圈很久后弹"本地服务未连接"，其实后台还活着。

**根因**：界面每 2.2 秒拿一次"全部状态"，后端把所有任务完整结果、所有草稿完整画面数据都读出来传（一条成片结果约 230KB，一份草稿画面约 73KB/条素材）；前端拿到后还要整理三遍；请求 30 秒超时就判"断线"。

**改法**：
1. 状态接口只返回"最近 20 条任务摘要 + 草稿列表摘要"（不含逐镜头时间线、不含每段画面数据）。
2. 新增两个详情接口：点开某条草稿/某个任务时再取完整数据。
3. 数据库查询加"倒序 + 条数上限"，并给创建时间加索引。
4. 前端只在数据真的变化时重画；空闲时把刷新间隔从 2.2 秒放宽到 30 秒，有任务时 1 秒。
5. 断线判定改为"连续 2 次失败"才提示，状态请求超时放宽到 60 秒。

**改完效果**：历史 1000 条任务时，单次刷新从几 MB 降到几十 KB；界面长期顺滑；不再误报断线。

**验证**：造 1000 条历史任务，量响应体大小与耗时；开关任务时界面无卡顿；断网 1 次不弹红条、断网 2 次才弹。

**风险**：接口形状变化，前后端必须同批改，相关测试断言同步更新（桌面端前后端同包，无外部兼容问题）。

### 2.4 批量渲染后其它任务排队（问题 4）

**现象**：提交 5 条生成后，再点"分析画面/下载素材"十几分钟没反应。

**根因**：后台只有 4 个干活位置，等渲染名额的任务也占着位置。

**改法**：渲染名额在"提交时"就申请（或给渲染单独一组位置），排队中的渲染不占公共位置；并发上限仍按设置里的"渲染并发"。

**改完效果**：批量渲染进行时，匹配/扫描/下载仍能立刻开始；取消某个渲染能马上让出位置。

**验证**：提交 5 条渲染后立刻提交匹配，应在 2 秒内进入"处理中"。

**风险**：低。注意别把"渲染并发"设置改坏——上限不变，只改排队位置。

### 2.5 成片成功却显示失败（问题 5）

**现象**：任务红字失败，但成片文件夹里已有完整视频。

**根因**：成片用硬链接发布；清理临时目录时若文件被占用，清理报错把整个任务判失败。

**改法**：清理临时文件一律"失败就跳过"，不影响成片结果；失败时留一条提示"临时文件将在下次启动时清理"；启动时清理超过 7 天的临时目录。

**改完效果**：占用成片时，任务仍显示"已完成"，成片可正常预览。

**验证**：用播放器占住成片再渲染一次，任务应为成功。

**风险**：极低。

### 2.6 取消丢结果、莫名"可能已计费"（问题 6）

**现象**：结果已收完时点取消，什么都没留下；或者配置错导致失败，却留下"上次可能已扣费"的记录，之后同一句一直被拦。

**根因**：① 收到完整结果后仍检查取消并直接报错，没先保存；② 配音在发请求**之前**就立"正在提交"标记，任何错误都改成"结果未知"。

**改法**：
1. 收到完整结果 → 先保存到缓存 → 再响应取消。
2. 只有"确实已发出、且可能被对方处理"的错误才记"结果未知"；提交前的确定性错误（密钥格式、目录不可写、文件占用）直接清掉标记。
3. 界面在"结果未知"时明确写"下次重试可能再次计费，请先核对"。

**改完效果**：取消不再丢掉付过钱的结果；配置错误不会再留下假警报。

**验证**：模拟"读完立即取消"，结果应保留；模拟密钥格式错，同一句应能直接重试。

**风险**：低。

### 2.7 磁盘只增不减（问题 7，新增）

**现象**：用半年后磁盘满，导入/渲染全部失败，报错还看不懂。

**根因**：配音缓存、画面缓存、HDR 转码副本、日志只增不删，程序里没有任何清理入口；失败残留的临时目录有时留在成片文件夹。

**改法**：
1. 设置页新增"存储管理"：分别显示 配音缓存 / 画面缓存 / HDR 缓存 / 日志 / 成片目录 的占用大小。
2. 提供"清理缓存"按钮（默认只清临时文件与 30 天前日志；清缓存会提示"下次使用会重新生成，可能产生费用"）。
3. 启动时自动清理 7 天前的临时目录。
4. 日志按大小/天数轮转，只保留最近 30 天。
5. **成片永远不自动删除**，只能用户自己去文件夹删。

**改完效果**：空间占用一目了然；磁盘不会再被悄悄吃满；清理是可预期、可撤销意识的动作。

**验证**：显示的大小与资源管理器一致；清理后磁盘释放；清缓存后已有草稿仍能打开（只是下次要重新生成）。

**风险**：清理范围必须白名单（只碰缓存/临时/日志），绝不碰成片、素材、草稿记录。

### 2.8 设置坏了打不开（问题 8）

**现象**：双击没反应或只弹"启动失败，请检查依赖"，重装也没用。

**根因**：设置文件解析失败/某个值非法就直接抛错，启动流程没有恢复入口。

**改法**：
1. 单个字段坏了用默认值继续，其他设置保留。
2. 整份文件坏了：改名备份为 `settings.unreadable.<时间>.json`，用默认值启动，并在界面提示"设置已重置，旧文件已备份"。
3. 数据库损坏：提供"备份并重建"入口（和现有"凭据重建"同一风格），不自动删任何用户数据。
4. 启动失败时给出可复制的具体原因，而不是笼统的"检查依赖"。

**改完效果**：配置坏了也能进软件，并能自己修。

**验证**：手写 3 种坏文件（非法 JSON、字段越界、空文件），都能启动并提示。

**风险**：低。备份文件名要固定规则，避免乱写。

### 2.9 保存设置会改掉混剪页（问题 9）

**现象**：混剪页填 40 秒/3 条，去设置页保存后变回 25 秒/1 条。

**根因**：保存设置后把设置值强行写回混剪页输入框。

**改法**：删掉这两行回写；设置页只负责设置页。

**改完效果**：两边互不影响。

**验证**：按原步骤复现，数值保持不变。

### 2.10 数字留空变成 0（问题 10）

**现象**：清空"背景音乐音量"保存后 BGM 静音；清空"清理区域顶部"保存后区域跑到最上面。

**根因**：空字符串转数字得 0，而 0 在合法范围内。

**改法**：前端空值不提交并提示必填；后端拒绝空值/缺字段。

**改完效果**：不会静默变 0。

**验证**：清空任一数字框保存，应提示"请填写"。

### 2.11 附：渲染时疯狂写数据库/日志

**改法**：进度变化 ≥1% 或 ≥0.5 秒才记录；日志只记状态变化（开始/完成/失败/取消）。

**改完效果**：渲染更快、硬盘不狂闪、日志不再每天几百 MB。

**验证**：5 分钟渲染的写库次数 ≤100 次。

## 4. 改完你自己怎么验（不花钱，10 分钟）

| 检查项 | 操作 | 通过标准 |
|---|---|---|
| 京东链接 | 粘 3 种分享文案：纯链接 / 链接后接中文 / 全角逗号分隔 | 都能读到商品标题 |
| 多规格商品 | 打开一个多颜色/多尺寸商品 | 30 秒内读到正确标题，不误报"已跳转其他型号" |
| 导入速度 | 导入一个 1GB 视频 | 不再出现几分钟卡住；取消立即生效 |
| 长期卡顿 | 连续生成 20 条视频后再看界面 | 点按钮无明显延迟，不弹"未连接" |
| 批量渲染 | 提交 5 条渲染后立刻点"自动匹配画面" | 2 秒内开始处理 |
| 成片假失败 | 用播放器打开一条成片后再生成一条 | 任务显示成功，成片可播放 |
| 取消 | 生成中点心取消 | 已收到的结果保留；不出现"可能再次计费" |
| 磁盘 | 设置页"存储管理" | 占用数字与实际一致；清理后释放；成片不受影响 |
| 设置坏了 | 手工改坏设置文件再启动 | 能打开，提示已备份旧文件 |
| 设置互不影响 | 混剪页填 40 秒/3 条 → 设置页保存 → 回混剪页 | 仍是 40 秒/3 条 |
| 空数字 | 清空"BGM 音量"保存 | 提示必填，不静音 |
| 进度日志 | 渲染 5 分钟看日志文件 | 行数受控（≤几百行），不暴涨 |

## 5. 不做什么（避免过度改造）

- 不替换数据库、不改框架、不引入新依赖。
- 不改渲染/音频/字幕算法（这些已验证正确）。
- 不动"历史记录不自动删除"的契约：只清缓存和临时文件，成片与任务记录保留。
- 不自动调用任何付费接口；需要真实接口验收的项单独列清单，由你点。
